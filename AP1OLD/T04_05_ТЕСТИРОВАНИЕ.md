## Полный сценарий PvE (игрок vs компьютер)

```bash
BASE="http://localhost:8080"
AUTH_ALICE="Authorization: Basic $(echo -n 'alice:secret' | base64)"

# 1. Регистрация
curl -s -X POST "$BASE/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"login":"alice","password":"secret"}'

# 2. Login (ответ — JSON-строка в кавычках, для URL убираем их)
ALICE_ID=$(curl -s -X POST "$BASE/auth/login" -H "$AUTH_ALICE" | tr -d '"')
echo "Alice UUID: $ALICE_ID"

# 3. Создать игру vs компьютер
GAME_JSON=$(curl -s -X POST "$BASE/game" \
  -H "Content-Type: application/json" \
  -H "$AUTH_ALICE" \
  -d '{"vsComputer": true}')

echo "$GAME_JSON"
GAME_ID=$(echo "$GAME_JSON" | python3 -c "import sys,json; print(json.load(sys.stdin)['id'])")

# 4. Ход alice (центр = X)
curl -s -X POST "$BASE/game/$GAME_ID" \
  -H "Content-Type: application/json" \
  -H "$AUTH_ALICE" \
  -d "{\"id\":\"$GAME_ID\",\"board\":{\"board\":[[0,0,0],[0,1,0],[0,0,0]]}}"

# 5. Получить игру
curl -s "$BASE/game/$GAME_ID" -H "$AUTH_ALICE"
```

> **Пояснение:** сценарий PvE: регистрация → login → `POST /game` с `vsComputer: true` → ход с доской где центр = 1 (X) → `GET` смотрит состояние. На доске: 0 пусто, 1 = X, 2 = O. Компьютер ответит своим ходом в теле POST.

## Полный сценарий PvP (два игрока)

```bash
BASE="http://localhost:8080"
AUTH_ALICE="Authorization: Basic $(echo -n 'alice:secret' | base64)"
AUTH_BOB="Authorization: Basic $(echo -n 'bob:pass2' | base64)"

# Регистрация
curl -s -X POST "$BASE/auth/register" -H "Content-Type: application/json" \
  -d '{"login":"alice","password":"secret"}'
curl -s -X POST "$BASE/auth/register" -H "Content-Type: application/json" \
  -d '{"login":"bob","password":"pass2"}'

# Alice создаёт PvP игру
GAME_JSON=$(curl -s -X POST "$BASE/game" \
  -H "Content-Type: application/json" \
  -H "$AUTH_ALICE" \
  -d '{"vsComputer": false}')
GAME_ID=$(echo "$GAME_JSON" | python3 -c "import sys,json; print(json.load(sys.stdin)['id'])")
echo "Game: $GAME_ID, state should be WAITING_FOR_PLAYERS"

# Bob видит доступные игры
curl -s "$BASE/game/available" -H "$AUTH_BOB"

# Bob присоединяется
curl -s -X POST "$BASE/game/$GAME_ID/join" -H "$AUTH_BOB"

# Alice ходит (X, центр)
curl -s -X POST "$BASE/game/$GAME_ID" \
  -H "Content-Type: application/json" \
  -H "$AUTH_ALICE" \
  -d "{\"id\":\"$GAME_ID\",\"board\":{\"board\":[[0,0,0],[0,1,0],[0,0,0]]}}"

# Bob ходит (O, верхний левый)
curl -s -X POST "$BASE/game/$GAME_ID" \
  -H "Content-Type: application/json" \
  -H "$AUTH_BOB" \
  -d "{\"id\":\"$GAME_ID\",\"board\":{\"board\":[[2,0,0],[0,1,0],[0,0,0]]}}"

# Информация о пользователе
ALICE_ID=$(curl -s -X POST "$BASE/auth/login" -H "$AUTH_ALICE" | tr -d '"')
curl -s "$BASE/user/$ALICE_ID" -H "$AUTH_BOB"
```

> **Пояснение:** PvP: Alice создаёт игроку без компьютера → state `WAITING_FOR_PLAYERS` → Bob видит её в `/available` → join → по очереди ходят X и O. Важно: каждый ход шлёт **полную** доску после своего изменения, с auth того, кто ходит.

## Частые ошибки

| Симптом | Решение |
|---------|---------|
| `* What went wrong: 26.0.1` | Java 26 — `export JAVA_HOME=$(/usr/libexec/java_home -v 21)` |
| `Task 'bootRun' not found` | Нет Spring Boot — пройди `T04_00_СБОРКА_ПРОЕКТА.md` |
| `permission denied: ./gradlew` | `chmod +x gradlew` из `src/TicTacToe_1.2_sql_auth` |
| `Connection refused` PostgreSQL | `brew services start postgresql@16` |
| `401` на `/auth/register` | Добавь `/auth/register` в `permitAll` **и** пропусти путь в `AuthFilter` |
| `401` на register, permitAll уже есть | `AuthFilter` режет всё без Basic — добавь bypass для `/auth/register` и `/auth/login` |
| `403` на `/game` с валидным Basic Auth | `anyRequest().authenticated()` в Security — замени на `permitAll()`, защита в `AuthFilter` |
| `400` на `/user/{uuid}` | UUID из login с кавычками — `tr -d '"'` при сохранении `ALICE_ID` |
| `Registration failed: login may already exist` | Пользователь уже есть — это норма, иди к login |
| `401` с правильным паролем | Проверь Base64: `echo -n 'login:pass' \| base64` |
| Hibernate не создаёт таблицу | `ddl-auto=update`, entity в пакете `tictactoe` |
| `column "state" contains null values` | Старые игры из Задания 1 — `psql -d tictactoe -c "DROP TABLE games;"` и перезапуск |
| `Not your turn` в PvP | Ходит не тот игрок — проверь `currentTurnPlayerId` |
| Minimax в PvP | В `makeMove` ветка `if (stored.isVsComputer())` |
| Компиляция: validateBoard | Интерфейс изменился — 3 параметра, см. часть 4 |

> **Пояснение:** таблица — типичные косяки на сдаче. `26.0.1` и `bootRun not found` — из части 0. `401` на register — забыли `permitAll`. Minimax в PvP — не разделили ветки в `makeMove`.
