## 2. JDK — критически важно (не Java 26!)

### Проблема

Если в терминале:

```bash
java -version
# openjdk version "26.0.1"  ← ПЛОХО для Gradle
```

Gradle падает с загадочной ошибкой:

```
* What went wrong:
26.0.1
```

Это **не баг проекта** — Gradle/Kotlin DSL не понимает Java 26.

### Решение — используй JDK 21 (или 18)

Проверь что установлено:

```bash
/usr/libexec/java_home -V
```

Должен быть хотя бы один из: **18**, **21**.

**Перед каждой работой** (или добавь в `~/.zshrc`):

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH="$JAVA_HOME/bin:$PATH"
java -version
# openjdk version "21.x.x"  ← ОК
```

### IntelliJ

**File → Project Structure → Project → SDK → 21** (Temurin или Corretto).

**File → Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JVM → 21**.

> **Пояснение:** у тебя в терминале может стоять Java 26 (Homebrew), а в IntelliJ — 18. Gradle берёт Java из **Gradle JVM**, не из Project SDK. Если видишь ошибку `26.0.1` — переключи и терминал: `export JAVA_HOME=$(/usr/libexec/java_home -v 18)`.

> **Пояснение:** `org/example/Main.java` — это заготовка IntelliJ «Hello world», она нам не нужна. Весь код будет в пакете `tictactoe`.

## 4. Настройка Gradle — `build.gradle.kts`

**Путь:** `src/TicTacToe_1.2_sql_auth/build.gradle.kts`

**Замени файл целиком:**

```kotlin
plugins {
    id("java")
    id("org.springframework.boot") version "3.2.0"
    id("io.spring.dependency-management") version "1.1.4"
}

group = "org.example"
version = "1.0-SNAPSHOT"

java {
    sourceCompatibility = JavaVersion.VERSION_18
    targetCompatibility = JavaVersion.VERSION_18
}

repositories {
    mavenCentral()
}

dependencies {
    // Web: Spring MVC, Tomcat, JSON (Jackson)
    implementation("org.springframework.boot:spring-boot-starter-web")

    // Тесты (пока не обязательны, но пусть будут)
    testImplementation(platform("org.junit:junit-bom:5.10.0"))
    testImplementation("org.junit.jupiter:junit-jupiter")
}

tasks.test {
    useJUnitPlatform()
}
```

> **Блок `bootJar { mainClass... }` НЕ нужен** — Spring Boot сам находит класс с `@SpringBootApplication`.
> Если IDE подчёркивает `springframework` **до** Gradle Reload — это нормально. Нажми **Reload Gradle Project** (иконка слона).

### Что здесь происходит — по строкам

| Строка | Зачем |
|--------|-------|
| `org.springframework.boot` | Плагин Spring Boot — даёт `bootRun`, автоконфигурацию |
| `io.spring.dependency-management` | Сам подбирает совместимые версии библиотек Spring |
| `spring-boot-starter-web` | HTTP-сервер + REST + JSON |
| `JavaVersion.VERSION_21` | Компилируем под JDK 21 |
| `bootJar` mainClass | Точка входа приложения |

> **Задание 1 (T04):** добавишь `spring-boot-starter-data-jpa` + `postgresql`.
> **Задание 2 (T04):** добавишь `spring-boot-starter-security`.

После сохранения: **Gradle → Reload All Gradle Projects** (иконка слона в IntelliJ).

> **Пояснение:** до этого файла у тебя был просто `id("java")` — обычная Java без сервера. Строка `spring-boot-starter-web` добавляет Tomcat (порт 8080), REST и JSON. Без Spring Boot plugin команды `bootRun` не существует.

## 5. Настройка Gradle Wrapper

**Путь:** `src/TicTacToe_1.2_sql_auth/gradle/wrapper/gradle-wrapper.properties`

**Замени содержимое:**

```properties
distributionBase=GRADLE_USER_HOME
distributionPath=wrapper/dists
distributionUrl=https\://services.gradle.org/distributions/gradle-8.10-bin.zip
networkTimeout=10000
validateDistributionUrl=true
zipStoreBase=GRADLE_USER_HOME
zipStorePath=wrapper/dists
```

**Почему 8.10, а не 8.14:** стабильнее с Spring Boot 3.2 + JDK 21. Gradle 8.14 + Java 26 у тебя уже ломались.

**Права на gradlew:**

```bash
chmod +x gradlew
```

> **Пояснение:** `gradlew` — скрипт, который сам качает нужную версию Gradle. `gradle-wrapper.properties` говорит какую именно (8.10). Так у всех в команде одна версия Gradle, не «что установлено на машине».

## 7. Первый Spring Boot класс — проверка что всё работает

Создай пакет и main-class **до** всего T03:

**Путь:** `src/main/java/tictactoe/TicTacToeApplication.java`

```java
package tictactoe;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@SpringBootApplication
public class TicTacToeApplication {

    public static void main(String[] args) {
        SpringApplication.run(TicTacToeApplication.class, args);
    }

    /** Временный контроллер — проверка что Spring поднялся. Удалишь позже. */
    @RestController
    static class HealthCheck {
        @GetMapping("/health")
        public String health() {
            return "OK";
        }
    }
}
```

**Теория:**
- `@SpringBootApplication` — старт Spring + сканирование пакета `tictactoe`
- `@RestController` + `@GetMapping` — endpoint `GET /health`
- Вложенный класс `HealthCheck` — временный, для теста (можно вынести отдельно)

> **Пояснение:** `@SpringBootApplication` говорит Spring «сканируй пакет tictactoe и всё внутри». `main` запускает встроенный Tomcat. `/health` — пробный endpoint: если curl вернул OK, Spring живой и можно писать T03.

> **Пояснение:** если в логах `Tomcat started on port 8080` и `curl /health` → OK — часть 0 сделана. Сервер останавливаешь Ctrl+C.

## 11. Частые ошибки на этом этапе

| Симптом | Причина | Решение |
|---------|---------|---------|
| `26.0.1` | Java 26 | `export JAVA_HOME=$(/usr/libexec/java_home -v 21)` |
| `Task 'bootRun' not found` | Нет Spring Boot plugin | Шаг 4, Gradle Reload |
| `permission denied: ./gradlew` | Нет прав | `chmod +x gradlew` |
| Порт 8080 занят | Старый процесс | `lsof -i :8080` → kill |
| Spring не находит beans | Класс не в пакете `tictactoe.*` | Перенеси файлы в `tictactoe.web...` и т.д. |
| Gradle долго качает | Первый запуск | Подожди, нужен интернет |
